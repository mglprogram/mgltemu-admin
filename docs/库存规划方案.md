# 库存规划方案（TEMU + SHEIN 统一口径）

> 2026-11-12 起草。目标：把现在「可售 ≤3 天就清零」的单阈值规则，换成一套**能算、能解释、能验证**的库存策略：
> 什么时候清零、什么时候开预售、补多少、补到多少天，都有公式和理由。

---

## 一、先说结论

| 现在 | 改成 |
|---|---|
| 可售天数 ≤3 天 → 清零（固定阈值） | **可售天数 < 预计到货天数（ETA）+ 缓冲** 才清零；有在途且在 ETA 内 → 开预售而不是清零 |
| 补货量拍 20 件 / 按档位 | **补到目标水位 S**：`S = min(μ_店 × DOS, 仓内 − 他店需求 − 安全库存)` |
| 安全库存 = 日均 ×1 天（或 5 件保底） | `SS = z · σ_日 · √L`（服务水平 z，实际交期 L，日需求标准差 σ_日） |
| 交期固定 45 天 | 用**头程实际预测上架日**（`shipment-track.json` 的 `predictedShelf`），分仓算 |
| 预售库存 = ceil(日均×7) | 预售锁 7 天只能用一次 ⇒ 填 `max(μ×7, 覆盖到下次窗口)`，并校验 ≤ 在途量 |

一句话：**清零的触发条件从「卖得快」换成「卖得快 + 来不及补」**；补货量从「拍数量」换成「补到目标水位」。

## 二、外部约束（这些是硬边界，不是我们定的）

| 平台 | 规则 | 对库存策略的含义 |
|---|---|---|
| Temu 半托管 | 订单生成后 **14 个自然日**内须完成「入仓上架」，逾期按日计罚（有单笔上限）；较原 21 天收紧 [来源](https://erp.91miaoshou.com/blog/article_5776.html) | 断货成本 > 滞销成本。清零后必须能在 14 天内补上，否则等于自己制造罚单 |
| Temu 履约双指标 | **48 小时上网率** + 妥投时效，按月统计，任一不达标即处罚 [同上](https://erp.91miaoshou.com/blog/article_5776.html) | 库存策略不能只看「有没有货」，还要看「货在不在能 48h 上网的仓」 |
| Temu 在途预售 | 同一 SKU **7 天内只能开一次**，补货日期需在 7 日内到货（开启时平台弹窗明示） | 预售是稀缺动作，一次要锁满 7 天销量；不能今天开 20、明天再开 50 |
| SHEIN 半托管 | 没有在途预售，只能「清零 / 改库存 + 补货」 | 清零是**唯一**的刹车；踩下去就只能等补货 |
| SHEIN 库存导入 | 走后台模板 `SKU / 仓库编码 / 数量`（平台 SKU 码），绝对值覆盖 | 我们的脚本只能给「绝对值」，所以目标水位 S 必须一次算对 |

## 三、模型（v3）

### 3.1 需求

- 日均 **μ**：优先「该店该链接」的 7 天日均；没有就用全渠道日均按占比折算。
- 波动 **σ_日**：用日销量序列的标准差。
  ⚠ **我们现在用的是「3 天日均 / 7 天日均 / 14 天日均」三个数的标准差 —— 那是均值的离散度，会被 √n 稀释**（7 天均值的 σ ≈ 日 σ/√7），导致安全库存系统性偏低。改为：
  `σ_日 ≈ pstdev(日均3, 日均7, 日均14) × √(平均窗口天数)`，或直接用日粒度销量算。
- 趋势因子：`3天日均 / 14天日均 ≥ 1.3` → 起量，DOS ×1.4；`≤ 0.7` → 降温，DOS ×0.7（现有 v2 已有）。

### 3.2 交期 L

- 用**头程预测上架日**（按仓）：`L_仓 = predictedShelf − today`，取该 SKU 在途里**最早**的那一票。
- 没有在途/没有 ETA：`L = 45 天`（海运兜底），并打 `eta_missing` 标记，这类款**不允许"清零后靠补货兜底"**，只能靠预售撑。
- 分仓：加州3 与 Kansas 交期不同，各算各的 ROP；SHEIN 的「加州3 / Warehouse 加州3 / HX美西」同理。

### 3.3 安全库存与补货点

```
SS   = z × σ_日 × √L                  # z：A/B/C = 1.88 / 1.65 / 1.28（97% / 95% / 90%）
ROP  = μ × L + SS                     # 在库 + 在途 低于它 → 必须补
```

理由：`z·σ√L` 是「交期内的需求波动」缓冲；服务水平按 ABC 分级，A 类缺货代价最高。

### 3.4 目标水位与补货量

```
可支配  = 仓内 − 他店日均 × 本地天数 − SS_店        # 多店共仓，先扣别家的用量
S      = min( ceil(μ_店 × DOS_eff), 可支配 × share )  # DOS：A 7 / B 3 / C 1（可调）
补货量  = max(0, S − 当前挂单)
```

- `DOS_eff = DOS × 趋势因子`
- 封顶是硬约束：不能把别家店的货挂到自己链接上（现 v2 的 `share` + 他渠扣减已实现）
- 本店 7 天零销量但仓里有货 → 保底挂 `min_listing`（默认 5），否则链接永远起不来（现 v2 已有）

### 3.5 清零 / 预售 的判定（核心改动）

分两个口径，**别混**：

```
在库天数 D0 = 可用 ÷ μ                 # 仓里现成的货还能卖几天
覆盖天数 D1 = (可用 + 在途) ÷ μ        # 加上在途一共能覆盖几天
L = 交期（该 SKU 在途里最早那一票的 predictedShelf − today）
```

| 条件 | 动作 | 理由 |
|---|---|---|
| **`D0 ≤ 1 天`（硬线）** | **一律清零**；在途 7 天内到 → 同时开预售，否则只清零 | 只剩不到一天的货还挂着卖＝等着超卖（用户 2026-11-12 定） |
| `D0 ≥ L + 2 天` | 不动，只按 ROP 预警 | 仓里的货能撑到下次到货 |
| `D0 < L + 2` 且 **在途 ETA ≤ 7 天** | **开在途预售**（清零 + 开） | 7 天窗口能接上，预售锁 7 天正好 |
| `D0 < L + 2` 且 在途 ETA > 7 天（或无 ETA） | **只清零**，不预售 | 接了单也发不出，等于制造 48h 上网率罚单 |
| `D0 < L + 2` 且 **无在途** | **清零 + 拉急单** | 只能止损，同时进「急补」清单 |
| 线上挂 0、仓内有货、本店有销量 | **补挂**（不是清零） | 清零判断不能反过来把有货的链接关掉 |

> 对比现在：3 天阈值只看 D1 的近似（而且带在途口径不一致），会把「仓里 0 天 + 11-17 就到 118 件」的款
> 和「仓里 5 天、20 天后才到货」的款判成同一类。v3 用 D0 定"要不要动"，用 ETA 定"能不能开预售"。

### 3.5.1 用今天的真实数据验一遍（BHY-202504-5SetA，2026-11-12）

| 尺码 | 可用 | 在途 | μ(7天日均) | D0 | L(ETA) | v3 判定 | 今天实际做的 |
|---|---|---|---|---|---|---|---|
| S | 66 | 405 | 20.86 | **3.16 天** | 5 天 | **开预售** | 按你选的「3.16 > 3」没动 ❗ |
| M | 4 | 819 | 52.43 | 0.08 天 | 5 天 | 开预售 | ✅ 已开 |
| L | 2 | 608 | 27.86 | 0.07 天 | 5 天 | 开预售 | ✅ 已开 |
| XL | 1 | 716 | 28.14 | 0.04 天 | 5 天 | 开预售 | ✅ 已开 |
| XXL | 0 | 603 | 19.86 | 0.00 天 | 5 天 | 开预售 | ✅ 已开 |

**S 是 v3 抓出来的漏判**：仓里 66 件只够卖 3.16 天，而最近一票 11-17 才到（5 天），中间会断 2 天。
按新模型 S 也该开预售（在途 405 件、11-17 到，完全撑得住）—— 建议补开。

### 3.6 在途预售库存怎么填

```
预售量 = min( 在途件数,  max( μ × 7,  ceil(μ × 3) ) )   # 锁 7 天窗口
        且 ≥ min_listing（5 件）
```

理由：平台 7 天内只能开一次 ⇒ 这一次要把 7 天能卖的锁进去；但**不能超过在途**，否则到期履约不了。
现在的规则（`T > S+50 → S` 那套）保留作为上限收敛，但下限抬到 7 天量。

## 四、参数表（默认值 + 怎么调）

| 参数 | 默认 | 调整建议 |
|---|---|---|
| z（服务水平） | A 1.88 / B 1.65 / C 1.28 | 黑五/大促前整体 +0.2；清库存季 -0.2 |
| DOS | A 7 / B 3 / C 1 天 | 与「资金占用上限」挂钩，A 类可以给到 10 天 |
| 本地天数 | 3 天 | SHEIN 线上出单到发货的现实节奏 |
| 交期兜底 | 45 天 | 只有缺 ETA 时用；这类款在面板标红 |
| 清零缓冲 | 2 天 | 14 天入仓窗口内的操作余量 |
| 最小挂单 | 5 件 | 新链接试卖，低于它链接权重起不来 |
| 预售下限 | 7 天量 | 平台 7 天锁 |

## 六、验收指标（上线后每周看）

1. **断货率**：可售 = 0 的 SKU 数 ÷ 在售 SKU 数（目标 < 5%）
2. **超卖/逾期**：因缺货导致的 48h 上网率不达标单量（目标 0）
3. **清零误杀**：清零后 7 天内到货的 SKU 占比（> 20% 说明清太早）
4. **滞销**：可售 > 60 天的 SKU 占比（目标 < 15%）
5. **预售履约**：开了预售但补货日未到货的比例（目标 0）
