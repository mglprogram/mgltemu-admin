## 一、整条新流程（已走到的部分）

```
① 订单列表页（TEMU）
   → 切「待发货」页签（BEL 42 单）
   → 点表头「订单信息」全选框（勾满本页）
   → 前置断言：批量确认发货 = 0 且置灰、合并下单 = 0 且置灰
        （若是 >0，说明这批混了「已买面单待确认」的单，不能一起导出）
   → 点「导出订单」→ 确认导出（字段全默认，不勾「过滤已取消的商品」）

② 拿到导出文件（紫鸟店下载目录，不在系统 Downloads！）
   ~/AppData/Roaming/ziniaobrowserdatas/ziniao browser/TM-BEL-MGL/订单导出2026115001.xlsx

③ 按 J 列「SKU货号」去库存跟踪查（**不带店铺前缀**）
   → 优先看帕沃尔可用库存 → 再把订单拆成两份（两个平台发货）
   → 实际拆成三份：帕沃尔 / 恒信 / 缺货（缺货不能发）

④ 恒信那份 → 进领星 OMS（oms.xlwms.com/platform/order/list）
   → 从导出的 PO 单号开始搜 → 全选 → 勾选
   → 分配仓库&物流 → 分配勾选数据
   → 仓库 ZOO WAREHOUSE ⑥美西 (USW01)
   → 渠道 上传物流面单 (Upload_Shipping_Label)
   → 确定并审核
```

## 二、真机踩到的坑（每条都实测过）

| # | 坑 | 现象 | 正解 |
|---|---|---|---|
| 1 | TEMU 导出的文件**不在** `~/Downloads` | 搜遍 Downloads 没有 | 在 `ziniaobrowserdatas\ziniao browser\<店名>\` 下 |
| 2 | 「导出订单」按钮不是立刻导出 | 弹出「已选 N 个订单，确认要导出吗？」+ 字段勾选 | 要点弹窗里的「确认导出」 |
| 3 | SKU 正则丢了版本点 | `BEL-102303-6SetA1.1-XL` 被截成 `BEL-102303-6SetA1` | 字符集必须带 `.`：`[A-Za-z0-9.\-_]+` |
| 4 | 库存 JSON 的 `code/variant/size` 是**有损拆解** | `102104A`→`102104`、`6SetA1.1`→`6SetA` | 一律用**整串去品牌前缀**（BH/BK/BS/BS2/BLA/BEL）对码 |
| 5 | 同款多单会超卖 | `204203-4SetC-L` 本批 5 单，帕沃尔只有 2 件 | 按 SKU 汇总需求分配，只放够的那几单 |
| 6 | OMS 的「平台单号」有两个图标 | 点 `lx_combo_filter`（多行精确搜索）→ 恒 0 条 | 正确是同一行右侧的 `lx_combo_search`（放大镜，单值） |
| 7 | OMS 多行精确搜索填 42 行搜不出来 | 面板明明显示 42 行，点搜索恒 0 条 | **未解决**（本轮未查明；疑似该面板只支持特定字段/需回车确认） |
| 8 | OMS 表头勾选框按 `th[0]` 取不到 | 取到「审核失败原因」，点了没反应、已选恒 0 | 固定左列在 DOM **最后**；认 `th .vxe-cell--checkbox` |
| 9 | 「分配仓库&物流」是 split button | 直接点只弹菜单（分配勾选数据 / 分配全部数据） | 必须再点菜单项才出弹窗 |
| 10 | 物流渠道**不是** `el-select` | 取「第二个 el-select」落空 | 是 `el-cascader`（两级：分组 → 渠道） |
| 11 | 「确定并审核」不等于审核通过 | 仓库/渠道分配成功，但审核失败 | 真实原因写进「审核失败原因」列（本次：`平台 SKU 未配对`） |
